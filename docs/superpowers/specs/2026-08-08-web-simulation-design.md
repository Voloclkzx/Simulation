# Веб-интерфейс симуляции

## Цель

Добавить локальный браузерный интерфейс для существующей симуляции: показать карту и статистику, управлять ходами и плавно анимировать перемещения существ. Игровое ядро (`Units`, `map`, `actions`, существующий `Simulation` и консольный запуск) не изменяется.

## Границы решения

Новая точка входа `karty.web.WebMain` запускает встроенный HTTP-сервер JDK на `http://localhost:8080`. Существующий `karty.Main` продолжает запускать консольную версию без изменений.

Веб-слой сам создаёт `GameMap` и использует существующие `InitAction`, `TurnAction` и `RestoreGrassAction`. Поэтому правила размещения, голода, питания, размножения и восстановления травы остаются единым источником истины в уже написанном бэкенде.

## Сервер и API

`WebSimulationController` владеет состоянием веб-сессии: картой, номером хода, признаком паузы, интервалом автоперехода и последним снимком. Доступ к нему синхронизирован, чтобы одновременный запрос браузера не пересёкся с выполнением хода.

Сервер отдаёт статические файлы интерфейса и JSON API:

- `GET /api/state` — актуальный снимок: размеры карты, номер хода, статистика и все сущности.
- `POST /api/next` — выполнить один ход и вернуть новый снимок.
- `POST /api/play` — включить автоматическое выполнение ходов.
- `POST /api/pause` — остановить автоматическое выполнение.
- `POST /api/speed` — установить интервал между ходами в миллисекундах в безопасном диапазоне.

Каждая сущность в снимке имеет стабильный идентификатор. Его присваивает только веб-адаптер по идентичности объекта Java; классы сущностей не расширяются. Благодаря этому браузер точно определяет, какое животное изменило клетку.

## Клиентский интерфейс

Страница строится без внешних пакетов: HTML, CSS и JavaScript в ресурсах проекта. Она содержит:

- игровое поле с адаптивной CSS-сеткой;
- карточки количества травы, травоядных и хищников;
- кнопки «Старт», «Пауза», «Следующий ход»;
- регулятор скорости и номер текущего хода;
- короткую легенду условных обозначений.

Клиент опрашивает сервер во время запуска и после любой команды. Управляющие элементы блокируются, пока предыдущий запрос не завершён, поэтому один клик соответствует одному ходу.

## Анимация

Для каждого нового снимка клиент сопоставляет сущности по стабильному идентификатору. Если животное осталось на карте, но сменило координаты, его DOM-элемент плавно смещается из старой клетки в новую с CSS-переходом. Новая трава и рождённые сущности проявляются, съеденные или погибшие — исчезают. Препятствия не анимируются.

После завершения перехода DOM синхронизируется со снимком сервера. Таким образом, отрисовка не влияет на правила игры и не создаёт отдельное состояние симуляции в браузере.

## Ошибки и запуск

Некорректные команды API возвращают JSON-ошибку с HTTP 400, а непредвиденные исключения — HTTP 500 без остановки сервера. На странице ошибка показывается рядом с элементами управления.

Для запуска веб-режима после сборки используется отдельный класс `karty.web.WebMain`; сервер сообщает адрес в консоли. Никаких изменений в существующей консольной точке входа не требуется.

## Проверка

- Компиляция и существующие unit-тесты Maven проходят.
- `GET /api/state` возвращает корректные размеры, счётчики и уникальные идентификаторы сущностей.
- Один вызов `/api/next` увеличивает номер хода ровно на один.
- Интерфейс работает при ручном ходе, паузе и автозапуске, а животные визуально перемещаются между клетками.
